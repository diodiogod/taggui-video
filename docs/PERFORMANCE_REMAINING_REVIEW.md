Cached preview handler measured 7.768 ms with GUI timer delivery before readiness; actual native first-frame and cold-load GUI parity remain manual checks. This supersedes the earlier deferred-runtime status below. Native player creation, decoder fallback and reveal delays remain unchanged.

Impact medium for first external-backend video, high mechanism confidence, small effort, low-to-medium risk, GUI/audio testing required. This supersedes the audio-attribution uncertainty below. DLL loading is separately measured at 2165 ms in one cold sample; safe asynchronous runtime loading remains unimplemented and requires pending/ready/failed resolution without GUI waits or false fallback.

**Startup/lifecycle follow-up implemented:** `ImageListView.__init__` gives its owning scrollbar proxy a separate style instead of transferring the global application's style. Context-owned timer delivery in `main_window.py`, `image_list_dock.py`, `auto_markings.py`, `toolbar_manager.py` and `PipelineStepList`, plus a window-owned `MenuManager` focus slot, fix reproduced post-destruction callbacks. Impact: stability/correctness, high confidence in covered native teardown, medium combined effort, low-to-medium regression risk; GUI required. Complete suite passes 572 tests/four skips with explicit root deletion and normal GC. The Windows exit failsafe is retained; media/backend cleanup is not exhaustively established.

**Small startup cleanup measured:** `IdeogramCaptionEditor.__init__` and `PipelineEditor.__init__` remove redundant initial styling, keeping the same final CSS/pixels at 60/100/160% zoom. At 100%, isolated panel construction medians changed 28.860 → 16.758 ms and 12.799 → 8.119 ms. Impact small (~17 ms combined in this fixture), confidence high for the comparison, effort small, risk low, GUI required for panel opening and resizing. Broad lazy panels remain deferred.

**First-video startup is a focused next measurement:** `VideoPlayerWidget.__init__`, `load_video`/`_refresh_backend_selection`, `playback_backend.load_playback_backend`, and `ImageViewer._ensure_video_components` still do first-use work synchronously. These individual samples establish work/variability, not a real click-to-visible result or a proved driver attribution. Potential impact medium/high for cold first video, confidence medium in mechanism attribution, effort medium/large, risk medium/high, GUI required. **Crop-filter reader consolidated:** `ImageIndexDB._read_filter_crop` now uses `read_taggui_metadata`, preserving valid crop behavior while avoiding full foreign-workflow object retention and sharing bounded rejection across readers. ## Explicitly deferred or rejected

- **Search-mode clarification:** Current `pagination_threshold` defaults to 0, so ordinary small folders also use SQL pagination. The characterized differences compare SQL and proxy predicates, not a default small-versus-large folder switch. Nonpaginated mode remains selectable through a higher threshold; per-image membership helpers also invoke the proxy predicate during marking/undo workflows. Those callers require end-to-end reproduction before claiming a user-visible defect or choosing a canonical behavior.
- **Search semantics (M12):** Covered text differences are resolved by keeping current paginated behavior as the contract. Broader search-syntax changes, indexed-sidecar freshness and other predicate contracts remain separate candidates; changing default results is outside this consistency patch.
- **Durable scope cleanup (H10 remainder):** `ImageIndexDB.register_path_scope` intentionally retains immutable membership for concurrent readers. Age-based deletion can invalidate active queries across requests/processes. Require reader leases or another proven lifetime contract first.
- **Runtime/WAL maintenance (H9):** Python/SQLite packaging upgrades require packaged Windows and dependency compatibility validation. The original audit records a SQLite WAL-reset reliability concern, not observed TagGUI corruption or measured performance benefit. This is a separate reliability task; no runtime, WAL policy or checkpoint setting was changed here.
- **Filesystem validation and relocation (M11/A4):** deferred hydration can change when missing files, edits, crop/marks or captions become visible. Asynchronous folder rename must drain actual native handles with rollback; stopping waits is unsafe. No change to real-file mutation paths.
- **Quick Sort setup counts:** `QuickSortPanel._refresh_eligible_count` already defers hidden/scrolling/jumping work, but `QuickSortController.estimate_queue_count` still performs synchronous scope counts. Moving it to a worker requires an immutable profile/selection/database snapshot and changes pending readiness/label timing. Passing the existing live widget/model context to a worker is unsafe; this is not included as a mechanical asynchronous conversion.
- **Thumbnail failure caching:** deterministic corruption and temporary Windows lock/resource errors need different retry policies. A blanket persistent failure marker can strand valid media. Existing retry behavior preserved.
- **Framework/proxy/decoder rewrites:** no evidence incremental options are exhausted. Pure keyset navigation cannot replace arbitrary rank jumps. Bounding-rectangle alpha hit-testing changes selection behavior. Blind worker increases and persistent full workflow caches remain rejected.

The larger opportunities are real candidates, not promises. Their unresolved drawbacks are why they are excluded from the low-risk implementation batch; this review does not declare the entire application performance-complete.
